## Context

对齐 funde PRD `05_用户_我的订单_v1.0.md` §3.3 / §3.5 / §5.7（并被 §5.4–5.9 引用的售后闭环）：

- 申请阶段只采「申请退款原因」，**不**展示退货方式/物流
- 审核通过 → 订单主状态进入「退款/售后」（App `status=6`，仅退款/售后 Tab + 全部可见）
- 若存在已交付发货任务商品且退货未完成 → 列表卡片与详情售后卡展示「去退货」
- 用户选自行送回或快递寄回；快递寄回必填物流名称 + 物流单号
- 提交后回显退货信息并隐藏入口

当前 iOS：`OrderDetailAfterSaleView` 只读展示退款信息；列表售后卡无「去退货」。接口未出。

## Goals / Non-Goals

**Goals:**

- 锁定「去退货」展示条件与抽屉交互，写入 OpenSpec
- UI 可先按 funde `OrderReturnDialog` 搭壳，提交走占位直至 Apifox 就绪
- 列表与详情共用同一资格判断

**Non-Goals:**

- 不实现后台审核、金额核算、物流轨迹（5.9.4 正向物流）
- 不自造提交 API 路径/字段名
- 不在待收货 / 使用中 / 已完成等**申请入口**状态展示「去退货」

## Decisions

1. **展示条件（产品权威，对齐 PRD §3.5 + §5.7.1）**  
   同时满足：
   - 订单主状态 = 退款/售后处理中（`status=6`，非退款审核 `9`）
   - 存在发货任务商品，履约状态为：**已发货 / 已签收 / 已收货 / 待自提** 之一（PRD 原文；系统仅依据订单商品履约行判断）
   - 退货处理**尚未完成**（提交后隐藏入口；具体标志字段待接口，原型用 `returnHandledAt`）

2. **入口位置**  
   - 退款/售后 Tab 列表卡片操作区：「去退货」  
   - 售后详情（原订单详情壳 + 售后信息卡）：「去退货」按钮（与列表共用资格）  
   - 全部 Tab 若卡片为售后处理中且合资格，同样可展示（与 funde 列表共用 `canHandleOrderReturn`）

3. **抽屉交互（对齐 `OrderReturnDialog.vue`）**  
   - 标题「去退货」；二选一：自行送回 / 快递寄回  
   - 自行送回：只读展示送回地址（退货地址 / 机构地址，字段待接口）  
   - 快递寄回：物流名称*、物流单号*（必填校验）  
   - 取消关闭；提交成功 Toast 后关闭，刷新订单，回显并隐藏入口

4. **与申请抽屉分离**  
   `5.7.4` 退款/售后申请抽屉**禁止**出现退货字段；去退货仅审核通过后出现。

5. **接口闸门**  
   - 无 Apifox 前：资格可用本地/详情已有履约行做 UI 演示（若详情暂无履约状态字段则按钮隐藏，不强行 mock 假 id）  
   - 有文档后：仅按文档字段解码与提交，再打开真实网络

## Risks / Trade-offs

| Risk | Mitigation |
|------|------------|
| 履约行状态枚举与 PRD 中文不一致 | 接口出后用文档枚举映射；spec 保留 PRD 语义表 |
| 无「退货已提交」标志导致入口不消失 | 待接口字段；未接前禁止用本地假成功冒充线上 |
| 体验套餐无实物仍进售后 | PRD：体验套餐审核后直接核算，通常无「去退货」；靠履约行条件自然隐藏 |

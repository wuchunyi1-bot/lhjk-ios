## ADDED Requirements

### Requirement: 去退货展示资格

系统 SHALL 仅在退款审核**通过后**的退款/售后处理中订单上，按履约行判断是否展示「去退货」。申请阶段与退款审核阶段均不得展示。

对齐 PRD：`05_用户_我的订单_v1.0.md` §3.5、§5.7.1 / §5.7.2 / §5.7.5。

#### Scenario: 合资格展示

- **WHEN** 同时满足：
  1. 订单主状态为退款/售后处理中（App `status=6`）
  2. 订单商品履约行中存在发货任务商品，且状态为 **已发货 / 已签收 / 已收货 / 待自提** 之一
  3. 退货处理尚未完成（尚未成功提交自行送回或快递寄回）
- **THEN** 订单列表卡片与订单详情售后信息卡均展示「去退货」
- **AND** 列表与详情使用同一资格判断

#### Scenario: 不展示

- **WHEN** 任一不满足：状态非 `6`（含退款审核 `9`、待收货、使用中、已完成等）；无上述履约状态商品；或退货已提交完成
- **THEN** **不得**展示「去退货」

#### Scenario: 申请阶段无退货字段

- **WHEN** 用户打开取消订单 / 结算 / 退款/售后申请抽屉（§5.3 / §5.4 / §5.5 / §5.6 / §5.8 → §5.7.4）
- **THEN** 仅采集套餐简卡与申请退款原因
- **AND** **不得**展示退货方式、退货地址、物流名称或物流单号

### Requirement: 去退货抽屉（自行送回 / 快递寄回）

用户点击「去退货」后，SHALL 打开底部抽屉完成退货方式选择与提交。

#### Scenario: 方式选择

- **WHEN** 打开去退货抽屉
- **THEN** 标题为「去退货」
- **AND** 提供「自行送回」「快递寄回」二选一
- **AND** 未选方式点提交时提示「请选择退货方式」

#### Scenario: 自行送回

- **WHEN** 用户选择自行送回
- **THEN** 只读展示送回/退货地址（地址文案来自接口下发；缺失时不得编造假地址写死进请求）
- **AND** 提交成功后 Toast 确认，关闭抽屉，刷新订单，售后信息卡回显退货方式（及地址），并隐藏「去退货」

#### Scenario: 快递寄回

- **WHEN** 用户选择快递寄回
- **THEN** 必须填写物流名称与物流单号
- **AND** 缺失时分别提示选择物流名称 / 填写物流单号
- **AND** 提交成功后回显退货方式、物流名称、物流单号，并隐藏「去退货」

#### Scenario: 接口未就绪

- **WHEN** 提交退货的 Apifox 接口尚未发布
- **THEN** 可实现抽屉 UI 与资格判断骨架
- **AND** **禁止**向任意接口传 mock / 硬编码假 id 或假物流单号冒充成功
- **AND** 真实提交与字段映射 MUST 待文档到位后单独任务接入

---

### Requirement: 与 5.4–5.9 状态页关系

「去退货」不改变各状态 Tab 的申请入口矩阵；仅在售后处理中闭环内出现。

#### Scenario: 待收货 / 使用中 / 已逾期 / 已完成

- **WHEN** 用户在 §5.4–5.6 / §5.8 发起退款或结算
- **THEN** 提交后进入退款审核（全部 Tab）
- **AND** 审核通过进入退款/售后后再按本 spec 判断「去退货」
- **AND** 上述状态页底部**不**直接展示「去退货」

#### Scenario: 二级页

- **WHEN** 用户查看发货记录 / 自提记录 / 正向物流轨迹（§5.9）
- **THEN** 只读履约信息，**不**作为去退货入口
- **AND** 去退货物流为用户寄回信息，与正向物流轨迹分离

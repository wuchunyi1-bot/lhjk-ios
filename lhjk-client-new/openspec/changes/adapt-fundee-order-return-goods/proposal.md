## Why

PRD `05_用户_我的订单` §3.3 / §3.5 / §5.4–5.9 要求：退款审核**通过**进入「退款/售后」后，若订单存在已交付的发货任务商品且退货未完成，列表与详情展示「去退货」，用户选择**自行送回**或**快递寄回**。iOS 当前仅有售后信息卡，无去退货入口与提交流程；接口尚未发布，需先锁定产品规则与实现边界，避免自造 API 字段。

## What Changes

- 新增「去退货」资格判断、列表/详情入口、底部抽屉（自行送回 / 快递寄回）产品与交互规格
- 明确**仅**在订单主状态为退款/售后（处理中，`status=6`）且满足履约条件时展示；退款审核（`status=9`）、申请阶段、已完成历史**不**展示去退货
- 提交成功后回显退货方式（及快递物流信息），并隐藏「去退货」入口
- **接口未出**：实现阶段仅可搭 UI / 资格占位；请求模型字段待 Apifox 对齐后再接，禁止臆造 Body/Query

## Capabilities

### New Capabilities

- `order-return-goods`: 审核通过后「去退货」入口、自行送回/快递寄回抽屉、提交后回显与隐藏规则

### Modified Capabilities

- `order-list`: 退款/售后 Tab 卡片在合资格时展示「去退货」

## Impact

- PL：订单列表卡片、订单详情售后信息卡、新增退货抽屉组件
- BLL：退货资格计算（依赖订单状态 + 履约商品行状态；具体字段待接口文档）
- DAL：待接口发布后对接提交/回显 API
